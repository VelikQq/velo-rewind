# Цифродроч

Статическое приложение для итогов велосезона. Тёмная тема и перелистываемые карточки истории сезона. Сервер, API-ключи Strava, npm-зависимости и сборка не требуются.

## Запустить на GitHub Pages

1. Создайте репозиторий на GitHub с основной веткой **main**.
2. Распакуйте этот архив. Загрузите **содержимое** папки `velo-rewind` в корень репозитория: рядом должны находиться `site`, `tests`, `package.json`, `README.md` и `.github/workflows/pages.yml`. Скрытая папка `.github` обязательна для автоматической публикации.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Test and publish GitHub Pages → Run workflow → main → Run workflow**. После последующих push в main workflow запускается автоматически.
5. Дождитесь успешного выполнения. Адрес опубликованного сайта будет в **Settings → Pages** и в окружении **github-pages**.
6. Передайте этот адрес друзьям: каждый загружает собственный экспорт в своём браузере.

Загрузка ZIP в репозиторий сама по себе не развернёт приложение — нужны распакованные файлы. При загрузке через веб-интерфейс убедитесь, что `.github/workflows/pages.yml` тоже добавлен. Если ветка называется иначе, поменяйте `branches: [main]` в workflow.

На GitHub Free Pages доступен для публичных репозиториев; возможности приватных зависят от плана. Документация: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

Альтернатива без Actions: содержимое `site` можно поместить в корень репозитория и в Pages выбрать **Deploy from a branch → main → / (root)**. Тогда тесты и README храните вне публикуемого корня, если не хотите их публиковать. Все пути приложения относительные — проектный адрес вида `/<repository>/` поддерживается.

## Откуда взять тренировки

На сайте Strava: **Settings → My Account → Download your account → Get Started → Request download**. Дождитесь письма, скачайте и распакуйте архив.

Официальная инструкция: https://support.strava.com/en-us/articles/15401919-how-do-i-export-my-strava-data

В приложении выберите:

- `activities.csv` — итоги сезона по сводкам тренировок;
- всю распакованную папку — CSV дополнится подробными записями из файлов, связанных через Filename;
- несколько исходных FIT, FIT.GZ, TCX, TCX.GZ, GPX или GPX.GZ — анализ этих файлов отдельно.

Для максимальной статистики используйте папку вместе с CSV и исходниками. ZIP напрямую не поддерживается. Форматы FIT/TCX/GPX не гарантируют наличие мощности или пульса: они должны присутствовать в исходных записях. Если программа не распознала CSV, пришлите разработчику обезличенную строку заголовков и пример строки для добавления формата.

**В репозиторий не нужно загружать тренировки.** Сайт читает выбранные файлы в оперативную память браузера. Код не отправляет файлы в сеть, не использует аналитику, localStorage, cookies или внешние шрифты. CSP запрещает connect-запросы. Подложка карты загружается автоматически: запросы тайлов OpenStreetMap раскрывают IP и область просмотра, но не передают файлы тренировок. Страница приложения и её исходники доставляются GitHub Pages обычным способом. После закрытия/перезагрузки вкладки данные нужно загрузить снова; сброс удаляет ссылки на данные в интерфейсе. При импорте новой партии старая заменяется.

## Статистика

- Километры, часы движения, набор высоты, число тренировок и активных дней.
- Километры по месяцам, календарь поездок и самая длинная серия дней подряд.
- Самая длинная поездка, максимальное время движения и максимальный набор за поездку.
- Средняя мощность из сводок, максимальная мощность в файлах.
- Лучшие средние мощности за 5 секунд, 1, 5 и 20 минут из временных рядов.
- Время в абсолютных диапазонах мощности и пульса.
- Средний и максимальный пульс, средний каденс из сводок.
- Любимый день недели, частый час старта, число поездок по дням недели.
- Средняя скорость и поездки от 50, 100, 150 и 200 км.
- Фильтры по датам, улице/виртуальным поездкам и неизвестному типу спорта.
- Перелистываемые экраны rewind с дополнительными сравнительными карточками и итоговая карточка PNG 1080×1350.
- Явный деморежим с вымышленными данными.

## Тепловая карта маршрутов

Загрузите распакованную папку экспорта с исходными FIT/TCX/GPX. В блоке «Дороги твоего сезона» отображаются маршруты за выбранный период. CSV без исходных файлов не содержит временного GPS-трека. Виртуальные/indoor-поездки не отображаются на карте.

Маршруты рисуются линиями в Canvas-тайлах штатного GridLayer Leaflet. Проекция, упрощение линий для четырёх уровней детализации и пространственные индексы готовятся при импорте. При зуме обрабатываются видимые тайлы; совпадающие экранные сегменты одной частоты не рисуются повторно. Маршруты и подложка используют общий механизм масштабирования Leaflet. Доступен зум колесом мыши.

Каждая тренировка учитывается один раз в каждой географической ячейке Web Mercator (8 пикселей на масштабе 16; физический размер зависит от широты). Это частота посещения ячеек разными тренировками, а не количество GPS-отсчётов и не точное число проездов по дороге. Между соседними точками интерполируются ячейки; разрывы более 2 км или 120 секунд не соединяются. Дорожный граф и map matching не используются. Один неполный GPS-отсчёт маршрутом не считается.

Перетаскивание — перемещение, колесо мыши, +/− или двойной щелчок — масштаб. «Все маршруты» возвращает общий обзор. Чёрно-белая затемнённая подложка OpenStreetMap включена всегда, переключателя нет. Фильтр применяется только к тайлам подложки, маршруты сохраняют цвет. Внешние запросы выполняются только для видимых тайлов с обычным HTTP-кешированием браузера; массового скачивания и prefetch нет. При отсутствии сети треки доступны на тёмном фоне. Атрибуция OSM видна, пока включена подложка. Leaflet 1.9.4 хранится внутри проекта; лицензия в `site/vendor/LEAFLET-LICENSE.txt`.

Источники: https://leafletjs.com/reference.html и https://operations.osmfoundation.org/policies/tiles/

## Расчёты и ограничения

Средние мощность/пульс/каденс: сумма `средний показатель × время движения` / сумма времени движения только для тренировок, где оба поля присутствуют. Это приближение по сводкам, не точное среднее всех отсчётов датчиков. Источник мощности может быть измеренным или оценочным; приложение не называет все значения измеренными.

Средняя скорость: сумма дистанций / сумма времени движения у тренировок с обоими значениями. Пустые значения не приравниваются к нулю. Для каждой основной суммы показана полнота данных.

Рекорды интервалов рассчитываются в рамках одной тренировки. Между соседними отсчётами значение считается постоянным. Нулевая мощность включается; интервалы с отсутствующими значениями или разрывами более 10 секунд исключаются. Возможные артефакты датчиков автоматически не удаляются. Лучшие 20 минут не выдаются за FTP. Диапазоны пульса не являются персональными тренировочными зонами или медицинской оценкой.

CSV: поддерживаются основные английские заголовки экспорта Strava и часть русских. Повторные столбцы берутся с конца. При двух Distance последний считается метрами; одиночный Distance — километрами. Если это не так, до импорта выберите метры/километры внизу страницы. Время в CSV — секунды или `HH:MM:SS`, высота — метры. Список заголовков доступен в `site/data.js`.

CSV сохраняет календарный день и час старта как в экспорте; AM/PM учитываются. Отдельные FIT/TCX/GPX используют UTC. При смешении источников граница дня может отличаться. Если точного типа спорта нет, он помечается Unknown и по умолчанию исключается; включите соответствующий флажок при необходимости. Для сравнения улицы и станка лучше использовать CSV: он надёжнее определяет тип.

TCX `TotalTimeSeconds` используется как время по таймеру кругов. Для отдельных GPX время движения и набор высоты не оцениваются; эти показатели останутся пустыми. При наличии только координат расстояние вычисляется суммой геодезических отрезков, без фильтра GPS-скачков. Для отдельных FIT берутся сводка session и record-сообщения. Поддерживаются оба порядка байтов, compressed timestamp и пропуск developer-полей. CRC не проверяется. Мультиспорт с несколькими session-сообщениями отклоняется — сначала разделите файл. Пользовательские developer-поля мощности не распознаются.

CSV + исходные файлы сопоставляются по basename Filename без .fit/.gz/.tcx/.gpx. По одному совпадающему имени импортируется один исходник. Загрузка одновременно одного и того же выезда с разными именами может привести к дублированию — не смешивайте дубли экспортов. Между разными импортами данные не накапливаются.

Ограничения импорта: 2500 файлов, 500 МБ суммарно, 50 МБ на файл после распаковки GZ, 1,5 млн временных точек. При превышении лимита точек импортируются уже прочитанные тренировки и выдаётся сообщение об ошибке. Для больших архивов выберите нужный сезон заранее. Современный браузер с ES modules, Canvas, dialog и DecompressionStream для GZ; при отсутствии распаковки GZ её можно выполнить вручную.

## Локальная разработка и проверки

Из корня проекта:

```bash
python3 -m http.server 8000 --directory site
```

Откройте http://localhost:8000. Двойной щелчок по index.html не рекомендуется: браузер может блокировать локальные ES modules.

Проверки расчётов и разбора файлов (Node.js 22+):

```bash
npm test
```

Браузерная визуальная проверка и запуск на реальном экспорте пользователя в этой поставке не выполнены. Автотесты используют синтетические данные, в том числе двоичный FIT. Публикация в ваш GitHub не выполнялась.

## Структура

- `site/data.js` — импорт и нормализация;

## Ты против себя

Отдельная карточка с 28 показателями за одинаковые даты текущего и прошлого года, с одинаковыми фильтрами спорта и улицы/станка. Группы: объём и регулярность; средние и рекордные дистанции/время, дистанционные пороги; средняя и максимальная мощность, лучшие интервалы 5 секунд, 1/5/20 минут; пульс и каденс; максимальная скорость и лучшая средняя за отдельную тренировку; FTP. Скорость хранится в м/с (CSV Strava, FIT и TCX), выводится в км/ч до десятых. Лучшая средняя — дистанция / время движения, с запасным значением из сводки при отсутствии этих данных. Максимальная скорость берётся из сводок или ряда скорости, без вычисления по шумным координатам GPS. Таблица показывает целые значения остальных величин и абсолютную/процентную разницу. Рекорды мощности требуют рядов мощности, средние из CSV взвешены по времени движения. Недоступные данные показываются как «—» и не превращаются в ноль. При нулевом базовом значении процент не вычисляется. Изменение меньше округления подписывается как приблизительно без изменений; время отображается до полных минут.

По умолчанию выбран расчётный FTP: 95% лучших непрерывных 20 минут за каждый период. Результат явно помечен как оценка; без полноценной записи мощности показывается пропуск. На ручной ввод известных FTP можно переключиться. Ввод сбрасывается при смене периода, фильтра или новой загрузке; не сохраняется вне вкладки. Известный ручной FTP можно сравнить даже без прошлогодних файлов. Дополнительный режим «95% лучших 20 минут» вычисляет ориентир, а не подтверждённый FTP. Период сравнения может включать длительное время, так что максимум сезона не равен текущему FTP на сегодняшнюю дату. Протокол теста, разминка, максимальность усилия и источник мощности не проверяются. Такой ориентир нельзя автоматически считать результатом FTP-теста.

Источники метода: https://pubmed.ncbi.nlm.nih.gov/31952081/ (20-минутный тест со специальной разминкой) и https://pubmed.ncbi.nlm.nih.gov/34749416/ (влияние разминки).

Краткое сравнение доступно отдельным экраном rewind при наличии прошлогодних тренировок. Изменение объёма, среднего пульса или средней мощности не интерпретируется как доказательство улучшения спортивной формы. В карточке показано покрытие данных обоих периодов.

При выборе текущего года конечная дата по умолчанию — сегодня по календарю браузера. Это позволяет сравнивать неполный текущий год с теми же датами прошлого года. Для прошедших лет по умолчанию выбирается весь год. Пользователь может явно изменить обе даты.


## Медиа сезона

Основная кнопка выбирает **всю распакованную папку экспорта** через `webkitdirectory`, включая вложенные папки. Выбирать тренировки по одной не нужно. Загрузка отдельных файлов оставлена как дополнительный вариант. ZIP по-прежнему нужно распаковать заранее.

Галерея «Моменты, ради которых ехал» связывает локальные файлы с тренировками по столбцу CSV `Media` / `Media File` / `Медиафайл` (несколько путей разделены `|`). Используются даты и фильтры тренировок, а не время изменения файлов. Имена совпадают без учёта регистра; папка-корень экспорта может называться произвольно. При нескольких одноимённых кандидатах связь не угадывается. Не найденные ссылки и файлы без связи отражаются в пояснении; последние не включаются в сезон.

Поддержаны JPEG, PNG, WebP, GIF, AVIF; видео MP4, WebM, MOV, M4V. Воспроизведение зависит от кодека и браузера; есть скачивание оригинала. Галерея показывает по 24 файла с кнопкой «Показать ещё». Фото загружаются лениво, видео — без предзагрузки и автозапуска. Файлы не читаются в общий буфер и не входят в лимит 500 МБ для тренировок. Вкладка держит ссылки на локальные File-объекты; браузер может использовать память при декодировании отображаемых фото и видео. При смене периода, импорте, демо и сбросе URL медиа отзываются. Публичный репозиторий содержит только код и вымышленные тестовые данные.


Читаемость: числа в сравнительной таблице — 16 px на компьютере и телефоне, с табличным начертанием цифр и увеличенными отступами. Таблица прокручивается горизонтально, первый столбец закреплён. Подписи и пояснения — преимущественно 14 px; элементы управления — 16 px.


Цвет маршрутов рассчитывается как непрерывное поле: частота исходных ячеек сглаживается ядром 3×3 и билинейной интерполяцией, затем цвет накладывается только на маску GPS-линий. Накопление непрозрачности от повторных линий устранено. Это визуальное сглаживание, исходные счётчики поездок и сводная статистика не меняются.
При отдалении для цветового поля берётся максимальная исходная частота в более крупной экранной ячейке, чтобы узкие часто посещаемые маршруты не исчезали при уменьшении. Это только визуализация: точные счётчики не пересчитываются.


В «Ритме сезона» столбики месяцев — кнопки: нажатие или Enter/Space выводит километры и число тренировок за выбранные даты и фильтры. Выбранный месяц подсвечивается. По умолчанию показан самый километровый месяц. При отсутствующей дистанции показывается пропуск с полнотой данных.


Кнопка «На весь экран» раскрывает карту, сохраняя центр, масштаб и состояние подложки. Повторное нажатие или Escape сворачивает её. При недоступном Fullscreen API используется разворот в пределах окна. После изменения размера вызывается invalidateSize без сдвига центра.


## PNG для соцсетей

Карточка 1080×1350 содержит дистанцию, число тренировок и время движения. Снизу — карта всех уличных GPS-маршрутов выбранного периода и фильтра, с автоматически подобранным масштабом независимо от текущего зума интерактивной карты. Карта показывает ту же тепловую окраску на чёрно-белой подложке; атрибуция OpenStreetMap сохранена. Перед скачиванием карточка отображается в предпросмотре. Для единственного отображаемого вида запрашиваются только необходимые тайлы, не более четырёх одновременно, с обычным кешированием браузера. При недоступной подложке скачивание останавливается с сообщением; без GPS в карточке явно указано отсутствие маршрутов. При смене фильтров или сбросе незавершённое сохранение отменяется.

Ссылки на рекордные тренировки: карточки дистанции/времени/набора, максимумы мощности и пульса, интервалы мощности, рекорды скоростей и расчётный FTP в «Ты против себя» (оба периода) и rewind. Адрес https://www.strava.com/activities/{Activity ID} формируется только по явному ID из CSV; файлы и их имена не используются для угадывания ID. Суммы сезона, средние сезона и вручную введённый FTP не привязаны к одной тренировке. Приватность тренировок продолжает действовать на стороне Strava.

Публикация: `node scripts/prepare-pages.mjs` создаёт `_site` с единой версией всех локальных JS/CSS и транзитивных импортов, вычисленной по содержимому сайта. Workflow публикует `_site`. Рекордные числа кликабельны без подчёркивания и отдельных текстовых ссылок; над карточками показано покрытие ссылками Strava.

PNG-карточка видна в предпросмотре сразу после импорта. Она автоматически обновляется при смене года, периода и фильтров. Скачивание сохраняет готовый предпросмотр без повторной загрузки карты. Устаревшая подготовка не перерисовывает новый период; ошибки видны и допускают повторную попытку. Заголовок — «Сезон ГГГГ» (диапазон лет для нескольких лет), без диапазона дат и строки полноты данных. Атрибуция OSM перенесена под карту.

Конструктор PNG: выбор показателей (дистанция, тренировки, время, набор, скорости, мощность, пульс, каденс, калории, активные дни, оценка FTP), включение маршрутов и прозрачный фон. При добавлении строк высота PNG увеличивается; недоступные данные показываются прочерком. Прозрачный вариант содержит только графику и текст без подложки карты и не загружает тайлы OSM. Шахматный фон виден только в предпросмотре. Переключение показателей повторно использует уже подготовленную карту данного периода.

Медиаблок по умолчанию свёрнут. При раскрытии создаются локальные превью; просмотр фото и видео — в модальной галерее на той же странице, со стрелками, клавишами ←/→, Escape и скачиванием оригинала. Переключение доступно по всем медиа выбранного периода, включая ещё не показанные миниатюры. При смене периода, закрытии и сбросе видео останавливается, ссылки на файлы освобождаются при смене набора.


Оценка подготовки: блок «На каком ты уровне?» использует FTP / массу тела и пять диапазонов Garmin FTP Ratings. Пороговые значения и названия сверены с русским руководством Instinct 3 AMOLED v6 (сентябрь 2026): https://www8.garmin.com/manuals/webhelp/GUID-2DA54DF8-8084-40ED-954F-EDA09C13B47F/RU-RU/GUID-1F58FA8E-09FF-4E51-B9B4-C4B83ED1D6CE.html . Категория определяется без округления по нижним границам: мужчины 2.23 / 2.79 / 3.93 / 5.05 Вт/кг, женщины 1.90 / 2.36 / 3.33 / 4.30. Пользователь выбирает шкалу, источник FTP (ручной или 95% лучших 20 минут), проверяет массу тела. Это уровень относительной мощности за выбранный период, не спортивный разряд или оценка здоровья/техники. Оценка по обычной тренировке может не отражать истинный FTP; происхождение мощности и максимальность усилия не подтверждаются. Методика профиля: https://www.trainingpeaks.com/blog/power-profiling/ .

Вес читается только из athlete weight / «Вес спортсмена» CSV (кг) или FIT user_profile.weight (поле 4, scale 10 кг по официальному Garmin FIT SDK: https://github.com/garmin/fit-python-sdk/blob/main/garmin_fit_sdk/profile.py). Вес велосипеда не используется. При слиянии CSV с FIT пустой вес CSV дополняется значением FIT. Для расчётного FTP автоматически используется только вес той же тренировки, иначе требуется ручной ввод. Для ручного FTP предлагается последний доступный вес выбранного периода с датой и источником; его актуальность нужно проверить. Вес из памяти пользователя не подставляется. Смена периода сбрасывает ручной FTP и подбор веса; источник и ручные исправления отображаются явно.

Отдельно показаны фактические самая длинная/долгая поездки, число тренировок и часы движения в среднем за полную календарную неделю выбранного периода (включая пустые недели), а также ряды мощности за 5 секунд, 1 и 5 минут в Вт/кг. Это описательные показатели, они не превращаются в общий придуманный балл. Неполные данные отмечаются; отсутствие FTP/веса/шкалы не порождает выдуманную категорию.

Исправлен фильтр импорта сжатых XML: GPX.GZ и TCX.GZ проходят в общий GZ-декодер, затем в XML-парсер, и связываются с CSV по тому же ключу, что и несжатые оригиналы.

Навигация по блокам: фиксированная левая панель на экранах от 1280px с зарезервированным местом в макете; на узких экранах — закреплённая снизу кнопка «Разделы» с раскрывающимся меню. Активный блок подсвечивается по прокрутке (обновления объединяются через requestAnimationFrame). Недоступные/скрытые разделы не показываются в меню. Переход к медиаблоку раскрывает его. Есть управление клавиатурой, Escape, закрытие по нажатию вне меню и учёт prefers-reduced-motion. Панель прокручивается отдельно при небольшой высоте окна.
